# Smallest complete design

- Choose the simplest implementation that meets the current requirements end to end.
- Reuse maintained dependencies and existing conventions before introducing abstractions.
- Separate concerns when they have different lifecycles or deployment requirements.
- Do not add compatibility layers, speculative configuration, or unfinished replacements.
- Prefer correctness and six-month maintainability to cleverness.
- Source: repository rules supplied through the project context.
